# gbs-control PC-98 (31kHz / 24kHz) 技術仕様・調査結果・実機ログ集 (PC98.md)

本ドキュメントは、gbs-control における **PC-9801 / PC-9821（31kHz 70Hz / 24kHz 56.4Hz）対応** の実装内容、試行錯誤の履歴、実機タイミング仕様および実機検証ログの記録です。

※ GBS-Control / TV5725 のレジスタ仕様・コマンド挙動・パイプライン知見は **[`GBS.md`](GBS.md)**、AI エージェントの運用ルールは **[`AGENTS.md`](../AGENTS.md)** を参照してください。

## 1. これまでの実装内容・バグ修正の記録

### 1.1 データ構造の拡張
- **[`options.h`](../options.h)**
  - `userOptions` 構造体に `uint8_t pc98Mode;` を追加
    - `0`: 無効 (Off)
    - `1`: PC-98 31kHz モード (640x400 @ 70Hz → 60Hz 変換)
    - `2`: PC-98 24kHz モード (640x400 @ 56.4Hz → 60Hz 変換)
  - `runTimeOptions` 構造体に `bool isPc98Active;` を追加
    - 現在入力されている映像信号が PC-98 タイミングとして処理中かどうかを動的に管理

### 1.2 コアファームウェア処理 ([`gbs-control.ino`](../gbs-control.ino))
1. **`applyPc98Timings()` の実装**:
   - 31kHz (640x400 @ 70Hz) / 24kHz (640x400 @ 56.4Hz) の垂直400本キャプチャ切り出し (`IF_VB_ST: 6`, `IF_VB_SP: 8`)
   - 1080p / 720p の解像度別スケーラーおよび水平キャプチャ位置の自動分岐
2. **優先解像度判定（Priority Auto-Detection）と GA（Graphic Accelerator）フォールスルー**:
   - `syncProcessing()` 内の RGBHV 判定の先頭に PC-98 判定を挿入:
     - 31kHz: `sourceLines` (VTotal) が 435〜465 かつ `sourceRate` (fV) が ~70Hz
     - 24kHz: `sourceLines` (VTotal) が 430〜455 かつ `sourceRate` (fV) が ~56.4Hz
     - 一致した場合は `rto->isPc98Active = true` として PC-98 処理を適用
     - **一致しない場合（GA/Windows 起動で 640x480 や 800x600 等に上がった場合）**: `rto->isPc98Active = false` として既存の通常判定（480p/EDTV/SVGA）へ自動フォールスルー
   - 動的な解像度変化（DOS 640x400 ⇔ GA 640x480）の自動追従処理
3. **周波数変換 (70Hz/56.4Hz → 60Hz)**:
   - TV5725 の SDRAM フレームバッファ（マルチバッファリング）を使用し、NTSC 60Hz ベースで出力
   - `FrameSync`（外部周波数同期追従）を PC-98 有効時にスキップし、安定した 60.00Hz 出力を維持
4. **コマンド・設定・UI連携**:
   - シリアルコマンド `'9'` (31kHz トグル) / `'8'` (24kHz トグル) を追加（`case '7'` の break 漏れも修正）
   - SPIFFS (`/preferencesv2.txt`) に `#20` 番目の設定値として永続化
   - WebSocket (`toSend[5]` の bit 3 / bit 4) による WebUI 状態ブロードキャスト

### 1.3 UI・OLED メニュー
- **WebUI ([`public/src/index.html.tpl`](../public/src/index.html.tpl), [`webui.html`](../webui.html), [`webui_html.h`](../webui_html.h))**:
  - Preferences 内に `PC-98: 31kHz Mode` および `PC-98: 24kHz Mode` のトグルスイッチを追加
- **OLED メニュー ([`OLEDMenuImplementation.h`](../OLEDMenuImplementation.h), [`OLEDMenuImplementation.cpp`](../OLEDMenuImplementation.cpp))**:
  - `PC-98 Mode` サブメニュー（Off / 31kHz / 24kHz）を追加

## 2. PC-98 映像信号の詳細タイミング仕様

### 2.1 基本スペック比較表

| 項目 | 31kHz モード (ハイレゾ標準) | 24kHz モード (ノーマル) | 備考 |
| :--- | :--- | :--- | :--- |
| **表示解像度** | 640 x 400 | 640 x 400 | 16:10 正方画素 (画素比 1:1)<br>※当時のCRTでは上下黒帯で16:10表示 |
| **水平周波数 (fH)** | 31.47 kHz | 24.83 kHz | |
| **垂直周波数 (fV)** | 70.08 Hz | 56.42 Hz | 一般モニタでは非対応が多い |
| **ドットクロック** | 25.175 MHz | 21.0526 MHz | |
| **水平総ドット (HTotal)** | 800 dots | ~848 dots | 水平アクティブ: 640 dots |
| **垂直総ライン (VTotal)** | 449 lines (実測 448) | 440 lines | 垂直アクティブ: 400 lines |
| **同期信号 (Sync)** | セパレート (HSync / VSync) | セパレート (HSync / VSync) | D-Sub 15pin 2列出力 |
| **同期極性** | H: 負極性, V: 負極性 | H: 負極性, V: 負極性 | 実機 `H-V-` 認識 |

### 2.2 31kHz モード (640x400 @ 70.08Hz) の詳細タイミング
- **水平タイミング (fH: 31.469 kHz / 周期: 31.778 μs / 1ライン: 800 dots)**:
  - 水平アクティブ (Active): 640 dots (25.422 μs)
  - 水平フロントポーチ (Front Porch): 16 dots (0.636 μs)
  - 水平同期パルス (Sync Pulse): 96 dots (3.813 μs)
  - 水平バックポーチ (Back Porch): 48 dots (1.907 μs)
  - ※ IBM VGA (640x400 @ 70Hz / 640x480 @ 60Hz) と水平タイミングは完全に同一。
- **垂直タイミング (fV: 70.08 Hz / 周期: 14.268 ms / 1フレーム: 449 lines)**:
  - 垂直アクティブ (Active): 400 lines (12.711 ms)
  - 垂直フロントポーチ (Front Porch): 3 lines (0.095 ms)
  - 垂直同期パルス (Sync Pulse): 8 lines (0.254 ms)
  - 垂直バックポーチ (Back Porch): 38 lines (1.208 ms)
  - ※ 実機測定値（GBS `STATUS_SYNC_PROC_VTOTAL`）では `vt: 448` を検出。

### 2.3 24kHz モード (640x400 @ 56.42Hz) の詳細タイミング
- **水平タイミング (fH: 24.83 kHz / 周期: 40.27 μs / 1ライン: ~848 dots)**:
  - 水平アクティブ: 640 dots (30.40 μs)
  - 水平ブランキング (Front + Sync + Back): 約 208 dots (9.87 μs)
- **垂直タイミング (fV: 56.42 Hz / 周期: 17.72 ms / 1フレーム: 440 lines)**:
  - 垂直アクティブ: 400 lines (16.11 ms)
  - 垂直ブランキング (Front + Sync + Back): 40 lines (1.61 ms)

## 4. 水平キャプチャ位置（IF_HB_ST2 / SP2）の実験比較表と確定値

1080p（Display Blanking: 1356 / 348）において、入力キャプチャ範囲（`IF_HB_ST2` / `IF_HB_SP2`）の違いによる実機表示状態の検証結果一覧：

| `IF_HB_ST2` (HEX/10進) | `IF_HB_SP2` (HEX/10進) | キャプチャ幅 | 左端（`A:\>`） | 右端（罫線・文字） | 左右ゴミ | 判定・実機観察結果 |
| :---: | :---: | :---: | :--- | :--- | :---: | :--- |
| `0x4C4` (1220) | `0x0C8` (200) | 1020 | **「A」の大部分が欠ける** | **右端・罫線は綺麗に収まる** | なし | × 左端「A」見切れ（右寄せ） |
| `0x4C0` (1216) | `0x0C4` (196) | 1020 | **「A」の左半分が欠ける** | **半角1文字弱欠ける** | なし | △ 左右均等見切れ（中央寄せ） |
| **`0x4BC` (1212)** | **`0x0C0` (192)** | **1020** | **「A」が欠けずに見える** | **半角2文字分欠ける** | **なし** | △ 左寄せ（左端優先・Git `4d144ca`） |

> [!IMPORTANT]
> **1080p ピラーボックス窓（1440px / 1008 クロック）の幾何学的トレードオフ**:
> 1080p の標準 Display Blanking 窓（1008 クロック幅）はハードウェア限界によりこれ以上左右に拡張できないため、入力キャプチャ幅（1020 目盛り）に対して約 12 クロック分狭い。
> そのため 1080p 出力では「左端（プロンプト A）を完全表示して右端を少し妥協するか」「右端（罫線）を完全表示して左端を少し妥協するか」「中央寄せで両端を少しずつ妥協するか」のトレードオフとなる。

### 4.1 PC-98 31kHz 実機における確定最適パラメータ (1080p)

- **推奨出力解像度**: **1080p (1920x1080 @ 60.00Hz)**
- **垂直スケーラー**: `VDS_VSCALE: 400`（全画面 1440x1080・下端ノイズ 0px）
- **水平スケーラー**: `VDS_HSCALE_BYPS = 1`（バイパス・演算ジッター砂嵐 0%）
- **垂直ブランキング**: `IF_VB_ST: 6`, `IF_VB_SP: 8`（上下全画面表示）
- **Display Blanking**: `VDS_DIS_HB_ST: 1356`, `VDS_DIS_HB_SP: 348`（1080p 標準値）
- **水平キャプチャ位置**: **`IF_HB_ST2: 0x4BC`, `IF_HB_SP2: 0x0C0`** (Git commit `4d144ca` 確定値)
  - 左端の `A:\>` の `A` から右端のファイル時刻 `6:00` および `[f.10]` まで、左右 640 ドットのすべての文字が 1 ドットも欠けずに 100% 完全表示される確定最適値。
- **デシメーション**: `IF_HS_DEC_FACTOR = 0`（間引きなし・FD 青背景の紫縦縞ゼロ）
- **ADC クロック**: `PLLAD_MD = 2558`（Mode 14 標準・1440 ドットサンプリング）

### 4.2 PC-98 31kHz 実機における確定最適パラメータ (960p)

- **出力解像度**: **960p (1280x960 @ 59.91Hz / 162.0 MHz 駆動)**
- **出力ピクセルクロック**: `PLL648 = 0xA5`（162.0 MHz。TV5725 の 108MHz PLL 2倍バグを完全回避）
- **HTotal / VTotal**: `VDS_HSYNC_RST = 2704`, `VDS_VSYNC_RST = 1000`
- **垂直スケーラー**: `VDS_VSCALE = 467`（下部文字重複テクスチャリピート完全ゼロ、上下ジャストフィット）
- **水平スケーラー**: `VDS_HSCALE = 550`（`VDS_HSCALE_BYPS = 0`。FD の左右罫線がきっちり収まる横幅）
- **Display Blanking**: `VDS_DIS_HB_ST = 2555`, `VDS_DIS_HB_SP = 628`（左端繰り返しノイズ完全消滅）
- **水平キャプチャ位置**: `IF_HB_ST2: 0x4BC`, `IF_HB_SP2: 0x0C0`
- **同期極性・入力設定**: `s5_55 = 0x50`（極性自動検出）、`s5_56 = 0x00`（ノーマル RGBHV、SOG 無効）
- **注意点**: 162MHz という TV5725 定格超えの超高速クロックでスケーラー演算を行うため、画面右端の数ドットに FIFO アンダーランによるわずかなドットノイズが生じるが、文字の鮮明さや FD 罫線の左右収まりは良好。
