# gbs-control PC-98 24kHz (24.83kHz) 技術仕様・調査結果・実機ログ集 (PC98_24kHz.md)

本ドキュメントは、gbs-control における **PC-9801 / PC-9821 の 24kHz (24.83kHz, 640x400 @ 56.42Hz) モード** に特化した実装仕様、設計方針、試行錯誤の履歴および実機検証ログの記録です。

※ 従来の 31kHz (70Hz) の検証ログは **[`PC98_31kHz.md`](PC98_31kHz.md)**、PEGC (640x480) 実機ログは **[`PC98_PEGC.md`](PC98_PEGC.md)**、TV5725 チップ全般のレジスタ仕様・パイプライン知見は **[`GBS.md`](GBS.md)**、作業規範は **[`AGENTS.md`](../AGENTS.md)** を参照してください。

## 1. 24kHz メインターゲット化の背景と設計方針

### 1.1 背景
- PC-9801 の本来の標準・ノーマル解像度は **24kHz (24.83kHz, 640x400 @ 56.42Hz)**。
- 31kHz は後期の PC-9821 や一部のハイレゾモードで使われるが、多くのレトロ PC-98 実機環境およびゲーム・DOS アプリケーションの本命は 24kHz である。
- 従来の 31kHz（70Hz）は高解像度スケールアップ（1080p/960p）の対象から外し、垂直 60Hz 変換と垂直 480 変換（480p 出力）にとどめ、**24kHz を高品質アップスケールのメインターゲット** として再設計する。

### 1.2 設計方針と 24kHz/31kHz 統合の経緯
- **24kHz と 31kHz の単一モード統合（実機確認により達成）**:
  - 実機検証の結果、24kHz 用にチューニングした専用アップスケールプリセット（1080p / 960p / 480p）が、31kHz 入力（70.1Hz）に対しても **そのまま完全に安定動作・高品質表示できることが判明**。
  - TV5725 は SDRAM フレームバッファを介して出力側で独立した 60.00Hz のクロック・タイミングを生成するため、入力側の垂直リフレッシュレート（56.4Hz vs 70.1Hz）や水平走査周波数（24.83kHz vs 31.47kHz）の差異がバッファで完全に吸収される。
  - どちらのモードも画面の有効解像度が同一の **640x400 ドット** であるため、ピクセル・ライン単位のスケーリング幾何学が共通化され、モードを分ける必要が解消された。
1. **メニュー・シリアル・内部モードの一本化**:
   - `pc98Mode = 1`: **PC-98 モード ON** (24kHz / 31kHz 自動両対応 & 60Hz 変換 & 1080p/960p/480p 出力)
   - `pc98Mode = 0`: Off (通常自動判定)
2. **アップスケール専用プリセット**:
   - **`pc98_1280x960.h` (4:3 本命)**:
     - TV5725 のスケーラー演算（`VDS_HSCALE`）が正常に動作する 162MHz クロック帯（108MHz 2倍バグ回避）。
     - 水平2.0倍(1280)、垂直2.4倍(960本)の高精細 4:3 表示。
   - **`pc98_1920x1080.h` (16:9 FHD ピラーボックス)**:
     - 148.5MHz 出力のためスケーラーバイパス必須 (`VDS_HSCALE_BYPS = 1`)。
     - 垂直2.7倍(1080本全画面フィット)、左右ピラーボックス表示。
   - **480p 出力 (720x480 @ 60Hz)**:
     - 垂直等倍（400→480ライン）変換。

## 3. 実機検証・実験ログ

### 2026-09-05: 24kHz メインターゲット化・初期ベースライン実機検証
- **対象モード**: PC-98 24kHz (640x400 @ 56.42Hz, VTotal実測 439)
- **実機検証結果**:
  - **960p (`1280x960`)**:
    - **完璧に表示**: 左側プロンプト（`A:\>` の `A`）は切れずに表示。FD（FILMTN等）の罫線も左右両方とも完全に画面内に収まっている。
    - 4:3 本命解像度として極めて高い安定性と画質を達成。
  - **1080p (`1920x1080`)**:
    - 初期状態では左側 `A` は出ているが右側が 4〜5文字見切れていた。
    - **失敗事例（教訓）**:
      - 水平サンプリング幅（`1_26` / `IF_HBIN_SP`）を増やしても位置は動かず、青背景が赤〜茶色に変色（クロック位相・色コンポーネント境界の崩壊）。1080p（スケーラーバイパス）では `1_26` の変更は厳禁。
      - 出力ブランキング・マスク（`DIS_HB_ST/SP`）を狭めると右端が隠れ、広げると SDRAM のラップアラウンド（左側ゴミ回り込み）が発生。出力境界は標準の `1356 348 / 1298 264` に固定が絶対。
    - **真因の特定と解決**:
      - ユーザーの的確な洞察通り、「入力サンプリング（Input Formatter）の切り出し窓が左に寄りすぎており、右端のピクセルがサンプリング不足で切り落とされていた（アンダーラン）」ことが真因。
      - 入力切り出し窓（`IF_HB_ST2` / `IF_HB_SP2`）をシリアルコマンド `'7'` で合計 +44目盛り（画面換算約 62px）右へシフト：
        - `IF_HB_ST2`: `0x464` (1124) → **`0x490` (1168)**
        - `IF_HB_SP2`: `0x068` (104) → **`0x094` (148)**
    - **最終結果**:
      - **左右ともにすべての領域が完璧に描画され、見切れが完全解消！**
      - 縦ゴミ・繰り返しノイズ・色化け・スクロールも一切なし。完璧な 1080p ピラーボックス表示を達成。
- **技術的知見**:
  - GBS-control のオリジナルの Mode 8（24kHz）は CSync（複合同期）を前提としていたため、セパレート同期（RGBHV）を扱う初期化（`SP_EXT_SYNC_SEL = 0` や `SP_HS_POL_ATO = 1`）および同期判定（`getVideoMode()` / `getStatus16SpHsStable()`）が Mode 14 のみに制限されていた。これを PC-98 全体（Mode 8 含む）に拡大したことで 24kHz でも完全同期を確立。
  - 31k モードと 24k モードでどちらも乱れず表示できるのは、表示ライン数が同一（400本）であり、TV5725 の SDRAM フレームバッファ（非同期マルチバッファ）によって 60Hz に吸収・安定化されているため。

### 2026-09-06: 24k / 31k / PEGC (480p) 完全シームレス相互切り替えの確立
- **背景と課題**:
  - 24k 起動から PEGC（MDISP 640x480 @ 60Hz）を起動すると、垂直周波数のジャンプにより高速スクロールが発生し、また切り替え経路によって画面左右の見切れが発生していた。
- **実機検証と解決策**:
  - PEGC（525本 60Hz）の同期追従には **`PLLAD_FS = 1`**（High Gain）が必須であることを実証。
  - 一方、400本 DOS（24k / 31k 共通）は **`PLLAD_FS = 0`**（Low Gain）かつ **`IF_HB_ST2 = 0x490`** でクロック位相が完全に一致し、左右見切れゼロとなることを解明。
  - `checkSync()` において走査線数（440本系 ⇔ 525本系）のみで `VSCALE`（400 ⇔ 480）と `PLLAD_FS`（0 ⇔ 1）を動的切り替えするアーキテクチャを確立。
  - 24k ⇔ 31k DOS 相互間ではレジスタ書き換えを行わないため判定チャタリングが原理的にゼロになり、24k 起動・31k 起動・PEGC 相互切り替えの全パターンで完全な正常表示・見切れゼロを達成。

### 2026-09-06: 24kHz 1080p 右端見切れ（4〜5文字）の完全解決と PLLAD_MD 整合性の解明
- **背景と課題**:
  - `IF_HB_ST2 = 0x490`（1168）を設定しているにもかかわらず、1080p 起動時に右端が 4〜5文字（約 32〜40 ドット）見切れる現象が発生。
- **真因の徹底解明**:
  1. **プリセット間の `PLLAD_MD`（サンプリングクロック分周比）の不整合**:
     - 9/5 当時のベースプリセット（`videoStandardInput = 8` / Medium Res や 960p）は、**`PLLAD_MD = 2345` (`s5_12 = 0x29, s5_13 = 0x09`)** で動作していた。
     - 一方、新設した `pc98_1920x1080.h` は `ntsc_1920x1080.h` から派生したため、`PLLAD_MD = 2558` (`s5_12 = 0xFE`) が残存していた。
     - サンプリングレート `2558` では、PC-98 のアクティブ 640 ドットが 1930 サンプル（IF 965 目盛り）に横へ引き延ばされてサンプリングされる。一方、`2345` では 1770 サンプル（IF 885 目盛り）となり、**約 160 サンプル（IF 80 目盛り ≒ 画面換算約 113px ≒ 約 14 文字分）コンパクトにサンプリングされる**。
     - このため、`2558` のまま `IF_HB_ST2 = 0x490` から取り込むと、右端の 4〜5文字が 1080p のピラーボックス表示枠（1008 目盛り）から押し出されて見切れていた。
  2. **H-PLL ゲイン `PLLAD_FS` によるクロック位相シフト**:
     - `s5_11` が `0x32`（`PLLAD_FS = 1` / High Gain）の場合、サンプリングクロックのロック位相が右へ数十クロック分シフトして見切れを助長する。
     - `PLLAD_FS = 0`（Low Gain、`s5_11 = 0x12`）とすることで定常位相遅延がゼロ基準に戻る。
- **実機検証と結果**:
  - `s5_12 = 0x29`（`PLLAD_MD = 2345`）、`s5_11 = 0x12`（`PLLAD_FS = 0`）を適用したところ、**ユーザー目視にて「きれいに納まった」ことを完全確認**。
  - `IF_HB_ST2 = 0x490` の正当性が完全に証明され、左端 `A:\>` から右端の時計 `:00`・罫線まで 1 ドットの欠けもなく完璧な 1080p ピラーボックス表示が恒久確立された。

### 2026-09-06: 960p / 480p の右端見切れ完全解消と全解像度統一入力キャプチャの確立
- **背景と課題**:
  - 1080p、1024p、720p が綺麗に収まった一方、960p と 480p において右端 1文字程度の見切れが発生。
- **真因の解明**:
  - 960p（`pc98_1280x960.h`）および 480p（`ntsc_720x480.h`）において、入力取り込み開始位置 `IF_HB_ST2` が初期値 `0x464` / `0x45C` のまま残っていた。
  - そのため、左側の黒い余白を余分に取り込みすぎて映像全体が右に寄り、右端の 1 文字が切り落とされていた。
  - さらに、960p の 1ライン長リミット `IF_HSYNC_RST` が `1172`（`0x494`）だったため、安全リミット（`0x464`）により `IF_HB_ST2` の右シフトがブロックされていた。
- **実機検証と解決策**:
  - `IF_HSYNC_RST` を `1279`（`s1_0e = 0xFF, s1_0f = 0x04`）に拡張し、`IF_HB_ST2 = 0x490`（`s1_18 = 0x90`）、`IF_HB_SP2 = 0x094`（`s1_1a = 0x94`）を適用。
  - 表示窓（Display Blanking）を `VDS_DIS_HB_ST = 2610`（`s3_10 = 0x32`）、`VDS_DIS_HB_SP = 626`（`s3_12 = 0x27`）に微調整。
  - **ユーザー目視にて「きれいに納まった」ことを完全確認**。
- **恒久アーキテクチャの確立**:
  - `applyPc98Timings()` において、PC-98 モード適用時はすべての出力解像度共通で `IF_HSYNC_RST = 1279`, `IF_HB_ST2 = 0x490`, `IF_HB_SP2 = 0x094` を一元適用するように統一。
  - これにより、1080p, 1024p, 960p, 720p, 480p の全解像度において、入力取り込みのズレによる左右見切れが原理的に根絶された。

### 2026-09-06: 480p 下部繰り返しノイズ（テクスチャリピート）の完全解消と 1:1 中央等倍レターボックスの確立
- **背景と課題**:
  - 480p 出力時、画面下部に約 80ライン分の繰り返しノイズ（画面上部の文字が下部に重複表示されるテクスチャリピート）が発生。
- **真因の解明**:
  - 480p（垂直 480ライン）の表示枠に対して、400本 DOS 映像が上端（ライン 24/32）からそのまま描画されており、400ライン描画終了後の余白（約80ライン）にスケーラーのテクスチャリピートが露出していた。
- **実機検証と解決策（1:1 ドットバイドット中央配置）**:
  - ユーザーの的確な設計方針「縦拡大（ボケ）より、400ライン切り詰めで 40ライン下げて中央に 400ラインを等倍で出す（上下各40ライン黒帯）」を採用。
  - 映像描画開始ライン `VDS_VB_SP` を `24` $\rightarrow$ **`64`**（+40ライン中央へ下げる）に設定。
  - 上側マスク終了ライン `VDS_DIS_VB_SP` を `32` $\rightarrow$ **`72`**（上黒帯 40ライン）に設定。
  - 下側マスク開始ライン `VDS_DIS_VB_ST` を `520` $\rightarrow$ **`488`**（ファンクションバーを完全に露出させつつ、400ライン直後から下黒帯で覆う）に微調整。
  - **ユーザー目視にて「画面下部の繰り返しは消えた、高さもいいかんじ、ファンクションバーは見えた、ゴミは出てない」ことを完全確認**。
- **恒久反映**:
  - `doPostPresetLoadSteps()` および `checkSync()` の動的切り替えブロックにおいて、480p かつ 400本系 DOS 検知時に上記パラメータ（`VB_SP = 64, DIS_VB_SP = 72, DIS_VB_ST = 488`）を自動適用し、PEGC 480本時は全画面（`24, 32, 520`）に切り替わる動的アーキテクチャを確立。
