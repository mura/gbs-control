## 1. 解決済み課題: PEGC (640x480) 表示中の解像度再選択・切替時の左側見切れ (RESOLVED)

### 現象 (解決前)
- 1080p 表示の状態で再度 1080p を選択すると、**左側が1文字ほど見切れる**（`IF_HB_ST2` が `0x464` から `0x490` に上書きされていた）。
- 960p 出力でも同様に左側が見切れる。

### 原因と解決策
1. **`applyPc98Timings()` による無条件上書き破壊バグの特定**:
   - WebUI から同一解像度（1080p 等）を再選択した際、`doPostPresetLoadSteps()` の最後で呼び出される `applyPc98Timings()` が、走査線数を考慮せず無条件に `IF_HB_ST2::write(0x490)`（DOS 400本用）を実行していた。
   - その結果、直前で設定された PEGC 最適値（`0x464`）が上書き破壊され、差分 44 ドット（`0x490 - 0x464 = 0x2C`）右にズレて左側が見切れていた。
2. **走査線数判定の追加と VTOTAL 2倍レート正規化**:
   - `applyPc98Timings()` 内に `STATUS_SYNC_PROC_VTOTAL` を取得して PEGC（490〜560）と DOS（420〜470）を判定するロジックを実装。
   - 同期プロセッサが過渡的またはモードによって VTOTAL を 2倍（800〜1150）でカウントする場合があるため、全箇所で `if (vt >= 800 && vt <= 1150) vt /= 2;` による正規化を追加。
3. **実機確認結果**:
   - 1080p 再選択後も `IF_HB_ST2 = 0x464`, `IF_HB_SP2 = 0x068` が完全に維持され、左側の見切れが一切発生せずジャストフィット表示が保たれることを確認。

## 2. 現在調査中の課題: 24k 400ライン 1080p 表示時における横幅短縮感および右側黒帯内の縦線ノイズ

### 現象 (ユーザー実機目視確認)
- **横幅の短縮感**:
  - 400ライン 24k 1080p 表示時に、横幅が前より短くなっている印象がある（ピラーボックスが太くなっている）。
  - プロンプト（左端）が右に寄っている印象はないが、右端が左側に詰まっている印象がある。
  - FD（ファイラー）を起動した場合、**FD の外枠青い罫線は欠けずにすべて見えている**（表示欠けではなく、アスペクト比/描画幅全体が縮んでいる状態）。
- **右側の縦線ノイズ**:
  - 画面表示（FD）の右端から数十px右に行ったところに、縦に黒に近い灰色のノイズが 1〜2px 見える。
  - 右端のノイズはチラチラと動いているように見える。
  - ノイズの位置は、ディスプレイ物理右端から数十px離れており、FD 右端から画面端（液晶端）までの黒帯の中で約 1/4 付近（内側寄り）に存在する。

### 技術メモ・仮説（現時点での調査知見）
1. **横幅（アスペクト比）に関する考察**:
   - 1080p は TV5725 の演算速度限界によりスケーラーバイパス（`VDS_HSCALE_BYPS = 1`）が必須。そのため横幅はスケーラーではなく ADC サンプリングレート（`PLLAD_MD`）で決定される。
   - 現在の `PLLAD_MD = 2345` は PC-98 アクティブ 640 ドットをサンプリングすると幅約 1250px（左右黒帯各 335px）。直前の PEGC（幅 1440px、左右黒帯各 240px）に比べて約 190px 横幅が狭いため、ピラーボックスが太く縦長に感じられる。
   - かつて `PLLAD_MD = 2558`（約 1420px 幅）を試した際は右端 4〜5文字が見切れたが、これは取り込み開始位置 `IF_HB_ST2` が `0x490`（右寄り）だったことが要因の可能性がある。
2. **右側縦線ノイズ（1〜2px チラチラ線）に関する考察**:
   - レジスタ現在値: `VDS_HB_ST = 1298`, `VDS_DIS_HB_ST = 1356`。
   - 映像描画終了位置（1298）から Display Blanking マスク境界（1356）までの間に **約 58 ピクセルの隙間（未描画の黒余白）** が存在。
   - TV5725 は 1080p（148.5MHz）出力時、スケーラーバイパス FIFO のアンダーラン耐性限界によりマスク境界線（1356）で 1〜2px のサンプリングジッター（走査線ジッターノイズ）を発生させるハードウェア特性がある。
   - 映像が 1298 で終わって隙間が空いているため、このマスク境界（1356）のジッターノイズが黒帯の中で露出して見えていると推測される。

### 今後の検証・アプローチ計画
- [ ] 960p（スケーラー稼働による基準 4:3 幅）と 1080p の横幅・アスペクト比を目視比較し、横幅の適正値を確定する。
- [ ] マスク位置（`VDS_DIS_HB_ST`）を映像描画端（`1298` 付近）まで引き締めて隙間のノイズを隠せるか検証。
- [ ] または、`PLLAD_MD`（サンプリングレート）と `IF_HB_ST2` のバランスを再調整し、映像を本来の 4:3（1440px）ピラーボックス幅まで自然に満たすことが可能か検証。
- [ ] 検証完了後、確定した物理知見を [`docs/PC98_24kHz.md`](PC98_24kHz.md) および [`docs/GBS.md`](GBS.md) に転記・恒久記録する。
